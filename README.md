# Альфа Конвейер — умный кредитный кабинет предпринимателя

Прототип цифрового кредитного конвейера для малого и микробизнеса (кейс «Умный кредитный кабинет предпринимателя», Альфа-Хак 2026). Клиентский путь и внутренняя обработка заявки объединены в один управляемый процесс на общем ядре: **заявка + неизменяемый журнал событий**.

> Все данные синтетические. Внешние сервисы (ЕГРЮЛ/ЕГРИП, ФНС «Прозрачный бизнес», БКИ) \*\*смоделированы\*\*. Подписание документов и выдача средств \*\*смоделированы\*\*. Реальных операций и доступа к системам Альфа-Банка нет.

## Что умеет

**Кабинет клиента:** выбор цели финансирования (а не продукта из каталога) → автозаполнение данных компании по ИНН → заявка → трекер из 5 шагов с пояснением «что дальше» → принятие оферты → подписание (симуляция) → выдача (симуляция). Если банку не хватает данных, клиент видит, что именно нужно добавить, и заявка автоматически возвращается в конвейер.

**Рабочее место банка (аналитик):** очередь заявок с SLA, разложение скоринга по факторам, reason codes, ручное решение с обязательным комментарием (одобрить / предложить другие условия / запросить данные / отказать), журнал аудита.

**Ядро процесса:** state machine (12 статусов) → knock-out правила → скоринг → кредитная политика продукта → **небинарный исход**: одобрение, встречное предложение, запрос данных, ручной разбор, отказ. Скоринг и кредитное решение разделены (см. `docs/ASSUMPTIONS.md`).

**Живое обновление:** интерфейс опрашивает сервер каждые 2 с; действие в одной вкладке (например, решение аналитика) меняет статус в другой.

## Быстрый старт

Требуется только **Docker** (Docker Desktop на Windows/macOS или Docker Engine + Compose v2 на Linux). Python и Node на хосте не нужны. Порт 8000 должен быть свободен.

```bash
git clone <URL репозитория>
cd <папка репозитория>
docker compose up --build
```

Откройте **http://localhost:8000**. База создаётся и заполняется учётными записями автоматически при первом старте. Остановка: `Ctrl+C`; запуск повторно: `docker compose up`. Полный сброс данных: `docker compose down -v`.

|Адрес|Назначение|
|-|-|
|http://localhost:8000|Веб-интерфейс|
|http://localhost:8000/docs|Swagger UI (OpenAPI)\*|
|http://localhost:8000/openapi.json|OpenAPI-спецификация (копия в `docs/openapi.json`)|
|http://localhost:8000/health|Проверка работоспособности|

\* Страница `/docs` подгружает скрипты Swagger UI с CDN (jsdelivr), для неё нужен интернет. Сам продукт работает полностью офлайн: у интерфейса нет внешних зависимостей.

## Пошаговая проверка (≈5 минут)

1. Войдите как предприниматель → «+ Новая заявка». На экране есть кнопки готовых сценариев — выбор подставляет ИНН, продукт, сумму и срок.
2. Пройдите пять сценариев; подробности и ожидаемые числа — в [`docs/TEST\_SCENARIOS.md`](docs/TEST_SCENARIOS.md):

   1. **Автоодобрение** → принять → подписать → «Средства выданы».
   2. **Встречное предложение** (меньше сумма, длиннее срок).
   3. **Нужны данные** → ввести выручку `18000000` и динамику `12` → заявка возвращается в конвейер и одобряется.
   4. **Автоотказ** (дисквалификация руководителя).
   5. **Ручной разбор:** откройте вторую вкладку, войдите как аналитик, примите решение — статус в первой вкладке обновится сам.
3. Убедитесь, что недопустимые действия блокируются (например, подписать неодобренную заявку через Swagger — HTTP 409).

## Архитектура

Модульный монолит с чёткими границами; подробности и диаграммы — в [`docs/ARCHITECTURE.md`](docs/ARCHITECTURE.md).

```
Браузер (static/index.html, vanilla JS)
        │  HTTP/JSON, Bearer-токен
FastAPI (app/main.py)           — тонкий HTTP-слой, валидация, коды ошибок
        │
Сервис (app/service.py)         — заявки, роли, журнал событий, транзакции, SQLite
   ├─ Ядро (app/core.py)        — state machine, скоринг, кредитное решение (чистые функции)
   └─ Адаптеры-моки (app/mocks.py) — ЕГРЮЛ/ЕГРИП, ФНС, БКИ (синтетические данные)
```

## Что не вошло в MVP (осознанно)

Реальные интеграции, ML-скоринг, залоговый модуль, электронная подпись, распознавание документов, LLM-ассистент, уведомления вне продукта (по условиям кейса почта/SMS не допускаются), мобильное приложение (запрещено условиями). Обоснование и дорожная карта — в `docs/ASSUMPTIONS.md` и `docs/ARCHITECTURE.md`.
